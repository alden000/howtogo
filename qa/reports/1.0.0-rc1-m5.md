**QA-52 (S3)**
- **Proof:** `scripts/smoke-deploy.mjs:81` `!/maplibre/i.test(html)` matches the inlined app CSS: `.mapbox .maplibregl-map`, `.maplibregl-ctrl-attrib` ×5 (`src/web/src/styles/app.css:151–159`, inlined by `inlineCss` since the engine round).
- The local `dist/index.html` and the preview `GET /` both have **0** occurrences of `maplibre-gl-` (the chunk) and no MapLibre `modulepreload`. The Director's suspicion (a modulepreload added by the integration round) is not the cause.
- **Repro:** `node scripts/smoke-deploy.mjs http://127.0.0.1:18797` → 28/29, exit 1.
- **Impact:** the post-deploy smoke always fails, and AC 33 makes a failure mean rollback.
- **Fix:** match the chunk only, e.g. `/(?:src|href)="\/assets\/maplibre[^"]*"/`. The budget (`budget.mjs`) and static-pwa checks already look at file names and pass.

**QA-53 (S3)**
- **Cause:** `src/web/src/styles/m5ui1.css:12` `.dots{…display:flex;flex-direction:column…}` was added by UI-1 for the privacy bullet list (`views/Privacy.tsx:59`). It is global and overrides `app.css:257` `.dots{display:flex;gap:6px}` used by the first-run step dots (`views/Welcome.tsx:61`).
- **Scope:** all sizes and both languages, not only 85 %. m5 "85 % text" fails with `flex-direction column`, 3 distinct tops.
- The baselines `M1-F1-lang` and `M5-F1-size-{85,100,200}` were re-recorded in UI-1 **with** the stacked dots, so dev-e2e cannot catch it.
- **Fix:** rename the privacy list class (`pvdots`, or scope it as `.pv .dots`). Re-record those 4 baselines in Docker; Creative checks.

**QA-54 (S3)**
- **Proof:** `node scripts/smoke-live.mjs http://127.0.0.1:18797` prints `smoke:live BLOCKED …`, then `Assertion failed: !(handle->flags & UV_HANDLE_CLOSING), file src\win\async.c, line 94`. The exit is 127 in Git Bash and 3221226505 from node. Node v24.19.0, 3/3. Without a URL (no fetch) it exits 2 correctly.
- **Impact:** the owner's machine is Windows, so a BLOCKED run reads as a crash and scripts can't tell BLOCKED from FAIL.
- **Fix:** in `scripts/smoke-live.mjs` (lines 91, 102, 168; same pattern in `smoke-deploy.mjs`), set `process.exitCode = n` and return, letting the event loop drain, instead of calling `process.exit(n)` right after `fetch`.

**QA-55 (S3, ruling)**
- `scripts/smoke-live.mjs:96` `if (hb.lta !== "key") blocked.push(…)`.
- The Director ruled that `/api/health` keeps `lta: key|proxy|none`, and the live production Worker reports `lta: proxy` (director-log, 0.3.0 LIVE: LTA data comes via the `whereisthebus-lta-proxy` service binding).
- As written, `smoke:live` stays BLOCKED on production unless the owner also sets `LTA_ACCOUNT_KEY`. OQ9 then never allows the `v1.0.0` tag.
- **Ruling needed:** either `proxy` counts as live (and the bus-arrival/alerts/lifts checks run through it), or the owner must set the key.

**QA-57 (S3, regression from 0.3.0)**

### (a) m4 AC 36: "Show the driver can't load offline in the second tab": test bug, not product

- **Cause:** `m4.spec.ts` blocks service workers for the whole file (`test.use({ serviceWorkers: 'block' })`), and `vite preview` serves chunks with `Cache-Control: no-cache`. Offline, tab 2 can get the lazy `tripSheets` chunk (and `present`, `guideModel`) only from the HTTP cache, and a `no-cache` entry can't be revalidated offline (`ERR_INTERNET_DISCONNECTED` on all three, then `chunk:failed`, `chunk:offline`). The dev's `sw:failed` is the block itself. This is not the ignoreVary class of bug.
- **With the SW allowed (the real product path),** the same steps serve `tripSheets`, `present` and the rest from the SW (`fromServiceWorker = true`), and the driver sheet opens offline. `tripSheets` is in the precache list. **Not S2.**
- A second test issue: tab 2 booted online, so Home's reverse geocode could finish before going offline. 6f.6 L6 then correctly shows the remembered address + time (`here-at`), not coordinates. That race is why the gate saw `here-none` and the dev saw something else.
- **QA fix (qa/ only):** AC 36 is now in its own `describe` with `serviceWorkers: 'allow'`. It waits for SW control, then cold-starts tab 2 offline: `here-none` + coordinates. Tab 1 checks the remembered address + time. 3/3.
- **Side finding, QA-60 (S4):** `preloadViews()` also warms the family `Viewer` chunk, which is deliberately not precached (`isViewerFile`). On every app session that is offline at the 3 s idle, this logs `chunk:failed` → telemetry `chunk_load` (and fetches an unused chunk online). That is false error counts in the AC 38/40 monitoring. **Fix:** leave Viewer out of the idle preload registry (or don't report `chunk:failed` while `navigator.onLine === false`).

### (b) m5 expired-cache eviction: test bug, not product

- The SW behaves as specified. Offline, the 25 h search and the 11 min route entries are not served (`net-error`) and are deleted, and the 1 min fresh entry is served (200).
- The final assertion demanded that the whole `api-v1` cache equal `['/api/search?q=fresh']`. But Home, after `controlled()`'s reload, caches its own fresh `/api/alerts`, `/api/lifts` and `/api/revgeocode` answers, which is legit and within TTL. So the test fails or passes depending on timing (it passed in the full run here, and failed 3/3 alone).
- **QA fix:** judge only the seeded keys. 3/3.
