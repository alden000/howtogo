**QA-21 (S3): no Notification permission request**
- Repro: run `grep -rn requestPermission src/web/src`. It finds only heading and location. `platform/web.ts` `notify()` returns unless `Notification.permission === 'granted'`.
- Expected (AC 30): when the user is briefly in another app, the get-off alert also arrives as a notification tagged `getoff`.
- Actual: in a fresh install the permission stays `default`, so nothing is ever shown.
- Fix: ask inside a user gesture (for example at Start, with a short explainer), or document the limitation. Check: QA "AC 30: the app asks for Notification permission".

**QA-22 (S4): headline size**
- Repro: start any trip at default text size and measure `[data-testid=current-step]`.
- Expected (AC 6): ≥ 32 px.
- Actual: 29 px, from the STYLE-GUIDE `step` token of 1.45 rem.
- Needs a PM/Creative ruling: amend the AC or raise the token.

**QA-23 (S4): wake-lock note comes back**
- Repro: wake lock rejected → note shows → ✕ → switch apps and come back. The note is shown again on every return.
- Expected: shown once per trip.
- Actual: `acquireWake()` sets `wakeLockFailed: true` on every failed re-acquire.

**QA-24 (S3, a11y): scrollable region not focusable**
- Repro: text size 200 % (dark zh or light en), reach G3 (waypoint) or H12 (arrival), run axe.
- Expected: no violations.
- Actual: `scrollable-region-focusable` on `main`. At 200 % the content scrolls, but `main` has no `tabindex` and no focusable child inside the scroll area, so keyboard and switch users cannot scroll to the lower buttons. (WCAG 2.1.1)

**QA-25 (S2, safety): Route home from the wrong place**
- Repro (demo, Home = Raffles Place): from Home (Toa Payoh), search "tan tock", Start, and ride the trip to "到了！" at Tan Tock Seng. Tap "回家的路".
- Expected (AC 47): H3 from **here** (Tan Tock Seng) to Home.
- Actual: `api.route` is called with `start = Toa Payoh Central (1.33465, 103.8491)`, the pre-trip location. H3 shows "从：Toa Payoh Central", and the routes offered start where the senior no longer is.
- Cause: `routeHome` sets `plan.from = null`. Routes then uses the module signal `here` from the last H1 `locate()`, which has no freshness rule and is never refreshed by the trip. The same stale `here` can affect any plan made right after a trip.
- Fix: refresh `here` from the trip's last good fix or `location.current()`, or give `here` a max age.

**QA-26 (S3): stale-drop leaves a dead screen**
- Repro: start a trip, wait until the stored trip is more than 24 h old (QA ages the stored timestamps), then reload on `/guide`. Android restores the tab URL after a kill.
- Expected (OQ5): the trip is dropped silently and the user lands on H1.
- Actual: `state:resume-drop` fires, but the user stays on `/guide` with "没有找到路线" (`state:guide-none`).
- Cause: `main.tsx` only redirects when `resumed` or `stale`.

**QA-27 (S3): version not bumped**
- `src/web/package.json` and `version.ts` are still `0.1.0`, so About, the Report and the SW all show 0.1.0. The owner cannot tell M2 from M1, and the gate artifact `howtogo-web-0.1.0-dist.zip.sha256` was overwritten (it was already modified in the worktree before this run).
- QA restored the committed M1 checksum file and recorded the M2 artifact under its own name (see Gate summary).

## Real-device items for the owner
Use the M2 spec's owner test script (≈ 45 min, Android Chrome, installed PWA). Battery ≥ 60 %, note the %.
1. Open the installed app and check voice is on. Note: **the version will read 0.1.0** (QA-27).
2. **Walk test (10 min):** Home tile → a place 600–900 m away → Start. Check that:
   - voice speaks;
   - the map turns with you (compass, AC 14);
   - after a drag, the map stays put until you tap Follow;
   - steps advance at corners and the stop without touching.
3. Walk one block the wrong way. Expect "没关系，你走了另一条路" and a new route within about 30 s.
4. Pull down the app switcher and come back: still guiding, screen still on. Swipe the app away and reopen: the trip continues; tap to turn voice on. Also try 1 minute in another app during a ride: **no notification is expected** (QA-21).
5. **Bus test (15 min):** a bus of ≥ 4 stops. The stop count goes down. Expect "下一站下车" **one stop before**, with voice, vibration and the saffron sheet, then "到站了，请下车" at the stop. Note any early or late alert and the stop name.
6. Phone in a pocket for one ride: does pocket view appear, and can you hear the alert?
7. Optional MRT leg: what happens underground (weak GPS note, "约 还有 N 站", I'm on / I got off)?
8. Arrive → "到了！". Tap "回家的路" and **check that "从" is where you are now** (QA-25: today it will be where you started). Note the battery %.
9. Settings → Report a problem → send it. Also note anything confusing, too quiet or too late.

Device-only checks: GPS thresholds, compass heading-up, real zh/en TTS voices, vibration feel, wake lock in the installed PWA (and iOS < 18.4), the iOS audio and compass unlock at Start, offline corridor tiles (AC 35/36), battery %/h (AC 41), and MRT tunnel behaviour.
