**QA-61 (S3)**
- **Repro:** `v11` "6g.4 hardware/browser Back". Open H2 from Home, tap the mic, then `history.back()`. H2 unmounts, so the mic stops on unmount, and the app is back on Home.
- **Expected (6g.4):** "Stop, the mic again, or Back end listening and keep the person on H2". Only the in-app Back does this: `Bar onBack={listening ? stopListening : undefined}` in `views/Search.tsx`. The router's `popstate` is not intercepted. The Developer flagged this as open in the UI round log.
- **Impact:** on Android the system Back is the usual gesture, and it throws away the search the person was speaking.
- **Fix:** while `voice === 'listening'`, have the router treat Back as a guard, as the H5 end-trip guard does: re-push the state, call `stopListening()`, stay. Re-check with `v11` 6g.4.

**QA-62 (S3)**
- **Repro:** `v11` "the explainer line never pairs…". Type `KKH` → `“KKH” means “KK Women's and Children's Hospital”`. Then type `Bishan Park` (Worker answer held 1.5 s). The line reads **`“Bishan Park” means “KK Women's and Children's Hospital”`** for the whole 300 ms debounce plus the network time, until the empty panel replaces it.
- **Cause:** `searchView(results, q.trim(), lang)` builds the alias line from the current `q` and the previous response's `alias`, because results are only replaced when the new answer lands.
- **Impact:** for a senior reading slowly, the screen states something false about the place they typed. On a slow phone network it can last for seconds.
- **Fix:** keep the query that each result set answered (e.g. `results.q`), and show the line only when it equals the current text. Or clear `alias` and `guess` when `q` changes.

**QA-63 (S3)**
